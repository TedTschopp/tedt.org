# Inside AI

TedT.org's browser-only adaptation of [Transformer Explainer](https://github.com/poloclub/transformer-explainer), pinned to commit `bfe50afba10b9b560b84143ee1107d977defa74f`. Copyright and MIT license are retained in `LICENSE-UPSTREAM.txt` and the published `assets/licenses/transformer-explainer-MIT.txt`. Diagram components, the five recorded examples, and educational explanations derive from that source. The site shell, accessible controls and tables, inference worker, validated downloader, tokenizer implementation, sampling correction, and branded styles are the TedT.org adaptation.

## Build and Verification

Use Node 20 or newer. Run `npm ci`, `npm test`, and `npm run build` in this directory. The build replaces only `inside-ai/assets/`; commit the generated assets. The main repository's CI checks generated-file drift, browser behavior, accessibility, and Jekyll output. Ordinary Jekyll builds do not need Node.

The Svelte 4/Vite 5 toolchain is intentionally compatible with the upstream Flowbite components. Every direct dependency is pinned and transitive versions are locked. Tailwind preflight is disabled, the final compiled CSS is scoped to `#inside-ai-app` after Svelte compilation (prefixing before compilation would cause Svelte to discard valid component selectors), and the legacy global layout and analytics were removed. No runtime package is fetched from a CDN. ONNX's external-WASM export condition avoids embedding duplicate WASM binaries in the worker.

## Data and Model

The model manifest is `https://tedtschopp.github.io/inside-ai-models/gpt2-bfe50afba10b9b56/manifest.json`. It lists the original 63 chunks (656,662,664 bytes). The downloader validates filenames, sizes, each SHA-256, and the pinned assembled SHA-256 `ccf64e934094054603c5b7bd98191f0fd2ea0315a81e9e0d8104070f64413119`. Only an explicit Enable action creates the worker and starts model requests. CacheStorage is limited to `tedt-inside-ai-gpt2-bfe50afba10b9b56-v1`. Cache access or quota failures allow in-memory inference; cancelling terminates the worker and outstanding requests. Clearing cache deletes only this named cache.

Single-threaded ONNX Runtime Web 1.23.0 runs inside the worker with self-hosted WASM. It reads one batch of 1–32 token IDs, returns a 50,257-element logit vector and all 720 attention matrices (12 blocks × 12 heads × 5 stages), and rejects incompatible output dimensions. Prompts and generated output remain in browser memory. No API key, server inference, telemetry, or browser-persisted prompt storage is used.

The GPT-2 byte-level BPE vocabulary and merge table come from Xenova/gpt2 commit `bf2c7f02e0b826c60d03af341171bde20893da66`, file `tokenizer.json`. The small local tokenizer follows OpenAI GPT-2's byte mapping and regex. Golden tests were independently produced with Hugging Face `tokenizers` 0.23.2 against that exact file, covering spaces, punctuation, contractions, newlines, multilingual text, emoji and special tokens. See model repository licenses for GPT-2 attribution.

## Evidence and Accessibility

The original examples contain real recorded token IDs, logits and attention matrices. Custom prompts use live model outputs. Both are labeled. Colored embedding, Q/K/V, weight and MLP vectors are illustrative, with explicit notices in the workbench and weight popovers. Full-vocabulary softmax and top-k/top-p filtering happen before limiting the displayed list to 50 rows. The original probability display's percent threshold was corrected. The diagram shows the retained leading candidates from the current sampling cutoff, with a visitor-selected limit of 5, 10, or 15 rows; the 50-row table remains available. Token labels, logits, probability bars, and the output fan share the same displayed rows and height. This display window never changes the sampling distribution.

The original complete diagram retains its expansion, vector, attention-head, block and popover interactions. Keyboard controls and topic buttons provide equivalent entry points; numerical tables expose attention stages and probabilities. Wide diagrams are contained within labeled scrolling regions. Three local Svelte compiler exclusions allow `tabindex="0"` on those labeled overflow regions so keyboard users can scroll them; there is no blanket accessibility-warning suppression. The diagram uses opaque label surfaces and high-contrast structural boundaries; expansion emphasizes paths without fading text. A dedicated browser gate measures composited text contrast (4.5:1) and essential boundaries (3:1) in both themes across collapsed, expanded, and weight-explanation states, supplementing Axe. The shell's existing theme supplies brand tokens, and reduced motion suppresses CSS, GSAP and D3 animation.

Important test hooks: `app-ready` carries `data-ready`, `data-mode` and `data-token-count`; controls include `example-select`, `prompt-input`, `generate-token`, `enable-model`, `cancel-download`, `clear-cache`, `model-status`, `model-progress`, `layer-select`, `head-select`, `temperature-control`, `sampling-mode`, `sampling-value`, `reset-example`, `evidence-mode`, `attention-table` and `numerical-output`.
